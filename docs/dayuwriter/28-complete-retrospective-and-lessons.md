# DayuWriter 全过程复盘、失误与可复用经验

## 0. 结论先行：完成了什么，未完成什么

截至本记录对应的代码版本，已得到下列不同层级的证据：

| 能力 | 证据等级 | 结论 |
| --- | --- | --- |
| CH340/GRBL 通信、三轴相对运动 | 真机观察、`ok`、最终 `Idle`、实测小位移 | 已建立受限 Python 控制链路 |
| 机械 P0 与 X/Y/Z 正方向 | 人工对准和小幅实测 | P0 是人工基准；`X+` 右、`Y+` 前、`Z+` 下 |
| D435i A RGB、深度、相机三维点 | Viewer 与 Python 采集 | 可用于只读相机数据；相机 XYZ 不等于写字机坐标 |
| A4 六 ArUco 纸面坐标映射 | `ready`、六标记和保留误差门槛 | 可显示纸面内红方块的 P0-XY |
| 端到端受监督动作 | 一次红方块 XY 与固定 `Z+1 mm` 现场演示 | 已做一次受限演示，不代表三维抓取 |
| 持续红方块跟随 | 代码测试与受监督现场循环 | 可 XY 移动、停 10 秒、返回 P0；需人看守 |

尚未完成或未获证实：杂草检测模型、任意目标识别、目标高度估计、深度驱动 Z 规划、抓取执行器、全行程精度地图、编码器闭环、自动回零、限位保护、独立急停以及无人值守运行。把“红色平面方块演示成功”描述成上述任何一项都是不准确的。

## 1. 项目过程的事实时间线

### 阶段 A：恢复原始写字机

- 设备由 Arduino UNO 兼容板、红色 CNC V3 扩展板、A4988、XY 步进电机/同步带/导轨、Z 电机/丝杆和 12 V 电源组成。
- GRBL 能接受命令、软件坐标会变化但电机不动，最初暴露了“通信成功与动力链成功不同”。最终确认电机 12 V 必须通过 CNC V3 的 `12-36V` 端子，且接线紧固；UNO 圆孔不能替代该电机供电路径。
- 之后以小幅 Jog 逐轴检查，X/Y 指令 `20 mm` 与实际约 `20 mm`，Z 累计下移约 `10 mm`。没有为了追求表面精度而盲改 `$100/$101/$102`。

### 阶段 B：建立可审查的 Python 控制

- 把 GRBL 命令编码、持久串口、状态等待、P0 相对工作区和 UI/控制台拆开。
- 用实际通信证据而非界面动画验收：命令得到 `ok`、最终为 `Idle`、操作者实际看到笔架运动。
- 确认 P0 只是人工纸面标记，重启、断电、手推、USB 重连、碰撞、异常或疑似丢步后都必须重新物理对准。

### 阶段 C：相机接入和失败诊断

- D435i A 在 Viewer 中确认 RGB/Depth，Python 获得对齐深度和相机坐标点。
- 出现深度为零、帧超时、文件写权限和电脑环境差异。它们分别是无效深度像素、进程/USB/帧池问题、文件锁或路径问题、依赖不完整等，不是一个笼统的“相机坏了”。
- 早期手工像素到纸面拟合只用于验证坐标链。一次保留验证误差约 `28 mm`、另一次姿态变化后像素漂移约 `75 px`，证明它不能当作可迁移标定。

### 阶段 D：由手绘点改为可复现的 A4 参考板

- 手绘大小不一的红圈会让分割质心随尺寸和边缘改变，因此改用约 `10 mm x 10 mm` 平整、不反光红方块。
- 曾出现“100 mm 标尺打印成约 95 mm”的缩放错误。之后明确要求 A4 横向 `100%` 打印和 `99--101 mm` 实测门槛。
- 以六个 `DICT_4X4_50` ArUco 标记建立 A4 板，在每次相机启动时从当前图像恢复相机到纸面关系。质量门槛为六 ID 全见、平均保留误差 `<=1.5 mm`、最大 `<=3.0 mm`。
- 实际固定会话曾记录约 `1.3--1.5 mm` 平均误差、约 `1.7--2.35 mm` 最大误差。这是历史一次会话的证据，不是每次启动后自动成立的精度承诺。

### 阶段 E：显示、单次动作与持续跟随

- dashboard 在图像和侧栏显示红方块纸面坐标，但不拥有串口；严格 `state.json` 才是跟随程序的输入。
- 先以 P0 方块获得视觉残余基线，再先预览，后在人工前提下执行一次分段 XY，并做过固定 `Z+1 mm` 的演示。
- 连续模式要求三帧稳定目标；一次目标移动后到目标、停 10 秒、返回 P0，再等待目标至少变化 1 mm。网页显示的短暂缓存只改善视觉连续性，控制程序不接受缓存。

## 2. 已确认的失误与根因

### 2.1 AI 建议与工程流程的错误

| 失误或不足 | 已发生的后果 | 正确做法 |
| --- | --- | --- |
| 历史 Gemini 对话曾建议把 12 V 接 Arduino UNO 圆孔 | GRBL 看似工作而电机无力，增加排查时间 | 从电机实际供电链确认 CNC V3 `12-36V` 端子与极性，通电前做最小动作 |
| 早期没有一开始就统一固定尺寸红方块、实测打印比例、板面坐标方向 | 手绘圆点、缩放板和 Y 方向混淆导致无效或重复标定 | 先确定物理坐标约定、量尺、固定板和独立保留点 |
| 使用手工点拟合后过早期待整面可用 | 仅小区域可信的模型被误认为可外推 | 用未参与拟合的点验收，并用多标记参考板覆盖纸面 |
| 反复要求同类确认、分段过细 | 用户等待过久，简单验证推进慢 | 只保留动作时不可替代的物理检查；其余采用固定命令和清单直接执行 |
| 文档索引曾保留“D435i 尚未接入”的早期结论 | 项目状态与后续现场记录不同步 | 每次硬件里程碑同步更新索引，并标注记录日期和证据等级 |

历史 Gemini 的错误属于其对话内容；本复盘不会把它伪装成硬件事实或把它错误归给其他程序。作为后续协作者，正确责任是更早核查电机供电链，而不是沿用未经现场证实的对话结论。

### 2.2 最严重的软件安全事件：测试误碰真实 COM4

2026-07-29，新增连续跟随分支的自动化测试携带 `--execute`、`--physical-preflight`、`--z-drop-mm 1`，且当时分支顺序使其落入旧的单次真机路径。真实 `COM4` 接收并完成了约 `X+2.513 mm`、`X+2.513 mm`、`Z+1.000 mm`。

根因不是用户明确发起了一次测试性运动，而是测试没有注入假控制器，且真实端口与测试入口没有隔离。这是本项目最严重的软件安全失误。修复是：测试使用 fake controller；连续模式优先分支处理；连续模式拒绝非零 Z 下落；真机动作只能由单独、显式命令和现场物理前提触发。原始记录见 [连续跟随测试事故](baseline/2026-07-29-continuous-follow-test-incident.md)。

### 2.3 相机和环境问题被错误地概括

| 现象 | 已证实/合理原因 | 修正方法 |
| --- | --- | --- |
| `depth ... 0.0` | 采样像素无有效对齐深度，整帧可能仍有有效深度 | 搜索邻近有限正深度；记录采样像素，不把零深度等同相机损坏 |
| `Frame didn't arrive within 5000` | Viewer/旧 pipeline 竞争、USB 不稳定，或临时诊断把多个 frameset 保留在有限帧池中 | 相机单进程独占；丢弃预热帧而非累积 frameset；直连 USB 3.x |
| 网页仍能打开而没有图像/坐标 | HTTP server 存活，camera worker 已断连 | 看 `state/error`，停止旧进程并启动新会话 |
| Conda 环境能激活但缺 NumPy | YAML 的 pip 阶段被中断 | 用解释器导入检查；在同一环境补齐二进制 wheel |
| pytest 卡顿/中断 | Windows 缓存或临时目录行为干扰 | 使用 `-p no:cacheprovider --basetemp <user-writable-path>` |

### 2.4 动作逻辑和 UI 的不足

- 最初一次跟随命令使用了较慢单次路径，且没有配置“停留后返回 P0”，与预期的连续演示不同。后续把有限连续、目标变化触发、10 秒停留和返回 P0 做成显式模式。
- 早期短暂丢帧会直接使跟随会话中断；现实现会跳过暂时无效帧，并要求三个稳定样本。它不会拿旧坐标继续运动。
- 初始 `±60 mm` 演示范围曾拒绝一个约 `X=87 mm` 的有效目标。随后只扩展到已经人工测得且保留余量的 P0 相对工作区，而不是取消边界。
- 页面原始浮点值随深度和分割产生小波动。24 帧一次检查约见 `0.186 mm` 的 X/Y 范围；页面现显示整数和短暂“上次有效坐标”标识。这个显示缓冲不能、也没有进入控制计算。

## 3. 不应再犯的技术原则

1. **设备身份永远在本次枚举中确认。** `COM4`、相机序列号、固件、USB 类型、`MPos` 和可见标记数都可能随设备/会话变化。
2. **通信、动力、机械和视觉是不同层。** `ok`、网页显示、深度值和电机转动各自只能证明一层。
3. **P0 是人工物理事实。** 没有回零和编码器时，开环坐标绝不可伪装成绝对位置。
4. **标定必须量真实尺寸并使用保留点。** 拟合点误差小不等于独立位置准确；平面模型不适用于离开平面的目标。
5. **实时显示与控制数据分离。** 可为页面稳定性缓存显示，但控制只接受当前、有效、完整、稳定的传感器状态。
6. **测试绝不接触真机默认路径。** 测试注入 fake controller；真机接口单独、显式且有人值守。
7. **限制是证据不足时的工程边界。** 未经机械实测，不因用户希望更快/更远而提高 `500 mm/min` 或移除工作区。
8. **任何异常都先停止。** 机械风险先断 12 V；保存状态、错误与现场观察；修复后从最小可验证步骤恢复。

## 4. 此项目可迁移到其他机器人项目的流程

```text
写出坐标系和失败条件
-> 设备枚举与只读健康检查
-> 单执行器的最小物理动作
-> 每层保存原始证据
-> 感知仅显示
-> 标定使用实测尺寸和保留点
-> 预览建议动作
-> 小范围、有人观察的执行
-> 将失败变成测试、闸门和操作清单
```

这个顺序看似保守，但能比“先把所有模块连起来，再用连续动作查错”更快定位责任层，也能避免用软件解释机械危险。

## 5. 下一阶段的客观起点

若下一目标是“识别杂草并移动到其位置”，应从以下独立任务开始，而不是直接删除当前红方块限制：

1. 明确目标是否仍在参考纸面内；若不共面，建立相机到机器的三维外参与目标高度/碰撞模型。
2. 采集带尺量真值的工作区数据集，量化 XY 误差与重复性，而不是仅报告参考板误差。
3. 独立验证目标检测模型的类别、漏检/误检、遮挡与照明鲁棒性；红色阈值检测不可代替杂草识别。
4. 解决可靠回零、限位/急停、`Pn:P` 输入根因和 Z 行程安全，再谈自动接触或抓取。
5. 先在仿真或假串口测试完整规划，再进行有人观察的小范围实机验证。

后续若实现这些能力，应新增独立的验收记录。不能以本文件的红方块演示记录作为其完成证据。
