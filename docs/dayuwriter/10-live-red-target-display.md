# D435i A 实时红色目标空间坐标显示

## 本阶段结果

该程序只做以下实时链路：

```text
D435i A RGB + 深度 -> 对齐到 RGB -> 红色圆形中心像素 (u, v)
-> 有效深度 (m) -> 相机坐标 XYZ (m) -> P0 纸面预测 XY (mm)
-> 本机浏览器显示
```

它不导入串口模块，不打开 `COM4`，不发送 GRBL，也不能从网页控制电机。
页面出现的 `motion_permission: "display_only"` 是刻意的安全边界，不是故障。

## 已验证的适用条件

- 设备必须是 Camera A，序列号 `231122070403`。
- 相机、纸张、P0 和写字机不得相对移动；改变任一项后，现有标定失效。
- 红色圆形标记要平放在标定纸面上，不能悬空、翘起或贴在笔架上。
- 首次演示请把标记放在已标定的 `X=0–60 mm`、`Y=0–60 mm` 方形内。
- 现有工件只用一个保留的中心点 `(30, 30) mm` 验证过，记录误差为
  `0.724 mm`。它不是整块工作区域的精度证明，也不能用于自动运动。

推荐使用哑光、饱和红色的圆贴纸或红色圆形纸片，直径约 `15–30 mm`。
不要让其他大面积红色物体进入画面；程序会选择最大的合格红色连通区域。

## 启动

在 VS Code 的项目根目录终端运行：

```powershell
conda activate dayuwriter-control
python -m vision.realsense.live_red_target_dashboard `
  --serial 231122070403 `
  --calibration docs\dayuwriter\calibration\camera-a-current-pose-result.json `
  --port 8765
```

启动后浏览器打开：<http://127.0.0.1:8765/>。
程序持续运行时不要移动相机、纸张或 P0 标记；结束时在该终端按 `Ctrl+C`。

## 页面字段

- `target.center_uv`: 红色圆形质心的 RGB 像素坐标 `(u, v)`。
- `depth_m`: 在目标中心附近取得的有效、对齐深度，单位米。
- `camera_xyz_m`: D435i 相机坐标，单位米；`+X` 向右、`+Y` 向下、`+Z` 从相机向前。
- `machine_xy_mm`: 用本相机姿态的纸面标定矩阵预测的 DayuWriter P0 XY，单位毫米。
- `depth_sample_uv`: 实际读取深度的像素。若圆心是深度空洞，它可与圆心相邻。

状态含义：

- `ready`: 识别到一个合格红色目标，取得有效深度，并生成显示用 P0 XY。
- `no_target`: 没有合格的红色圆形；调整标记大小、颜色、位置或画面中的其他红色物体。
- `depth_unavailable`: 识别到红色目标，但其附近没有有效深度；保持标记平放，改善纹理或光照后重试。
- `camera_error`: 相机流或启动失败；确认 RealSense Viewer 已关闭、USB 数据线直连且序列号正确。

## 从显示到人工确认移动的界线

先在浏览器观察 `ready`，再把红色标记放到至少一个已知纸面点，比较显示的
`machine_xy_mm` 与标尺/纸面坐标。仅当显示结果经人工确认后，下一阶段才可在
独立的、持久化 GRBL 会话中进行一次有边界的 XY 移动。届时仍需重新确认：

1. 笔尖已经物理回到 P0；P0 是人工参考，不是编码器或回零开关。
2. 12 V 已接通，笔尖悬空，目标路径无障碍物，且 X/Y 均有足够余量。
3. 运动后等待 GRBL 状态为 `Idle`，并由人眼观察实际运动；单独收到 `ok` 只表示控制器接受了命令。

本阶段不自动 Z 轴，也不把 D435i 的 `camera_xyz_m` 直接发送给写字机。
